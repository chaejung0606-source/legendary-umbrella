# 신청자(APPLICANT) 감사 — 회귀 & 최종 결과

## 실행 환경

- 프로덕션 빌드(`npm run build`) 후 `next start -p 3100`, 로컬 Postgres(sadan2), Chromium 실브라우저.
- 스위트: `e2e/applicant.e2e.mjs`, `e2e/manager-regression.e2e.mjs`, 데이터 계층 IDOR 직접 테스트.

## 신청자 종합 (50/50)

- A 인증 경계(5): 비로그인 307 + `?next=/dashboard` + 로그인 후 원경로 복귀.
- B 세션(2): 새로고침/새 탭 유지.
- C 서버 권한(6): `/settings`·`/rfid` 미들웨어 차단, `/assets/new`·`/assets/[id]/edit` 페이지 가드(307).
- D 메뉴(6): 신청자 5개 노출, 설정·RFID 숨김.
- E 대시보드(4): 위젯 표시, "자산 등록" 숨김, "대여 신청" 표시.
- F 자산(8): 조회/검색/페이지네이션/상세, 수정·이동 숨김, 대여·반납 사용가능.
- G 대여(5): 복수 자산 검색 선택 + 드로잉 서명 + 동의 + 제출 성공.
- H 홍보(4): 출고 신청 생성 → 본인 취소 성공(타인 취소 버튼 미노출).
- I 소모품(4): 입·출고 가능, 물품등록·재고조정 숨김.
- J 반응형(4): 360/390/768/1366 무횡스크롤.
- K 로그아웃(1) + Z 콘솔 무에러(1).

## 관리자 회귀 (21/21) — 기존 기능 무손상 확인

- 관리자 로그인 → 8+ 페이지 접근(대시보드/자산/자산등록/노트북대여/대여/소모품/홍보/RFID/설정) 전부 200.
- 관리자 전용 버튼 정상 노출: 자산 등록, 소모품 물품등록·재고조정, 대시보드 자산등록 링크, 자산 상세 수정·이동.
- 홍보 승인 플로우: 신청 생성 → 관리자 승인 → (정리) 취소 정상.
- 설정 페이지 접근 정상.
- 콘솔 치명 에러 없음.

> 즉, 신청자 인가 가드(requireManager/requireLogin)와 UI 게이팅이 **관리자 경로를 막지 않음**을 확인.

## 테스트 데이터 처리

- 생성 데이터 전부 `[E2E-TEST]` 태그. 종료 후 정리 확인: 잔여 대여 0, 홍보 신청 0.
- 대여로 상태가 바뀐 자산(asset-178/179)은 `정상`으로 원복. (`e2e/cleanup.sql`)
- 운영 계정 비밀번호/개인정보는 코드·로그·문서·커밋에 미포함. 테스트 계정만 사용.
- 운영 Supabase에는 접속하지 않음(로컬 테스트 DB만 사용) → 운영 데이터 무영향.

## 최종 결론(판정): **배포 가능**

발견된 보안 결함(서버 액션 인가 누락, 홍보 취소 IDOR)과 UI 게이팅·모바일 오버플로우를 모두 수정했고,
신청자·관리자 스위트가 전부 PASS했다.

### 배포 전 확인(권장 체크리스트)

1. 프리뷰(작업 브랜치, Vercel Preview)에서 신청자 계정으로 로그인 → 위 A~K 흐름 눈으로 확인.
2. 프로덕션 시드에 **E2E 테스트 계정이 포함되지 않았는지** 확인(현재 시드/커밋 미포함).
3. `AUTH_SECRET` 운영 값 설정 확인(기본 개발 시크릿 사용 금지).
4. 운영 배포는 사용자의 "배포해줘" 요청 시에만 프로덕션 브랜치로 진행.
