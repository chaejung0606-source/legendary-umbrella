# 신청자(APPLICANT) 테스트 계획

## 대상 / 도구

- 대상 역할: `user`(신청자), 계정 `applicant@e2e.local`(role=user, perms=[dashboard,assets,loans,consumables,promo])
- 도구: Playwright(Chromium) 실브라우저 자동화 + 서버/데이터 계층 직접 호출(tsx)
- 실행 스위트: `e2e/applicant.e2e.mjs`(50), `e2e/manager-regression.e2e.mjs`(21)
- 원칙: 검증/권한/기능을 **제거하지 않고** 실제 화면·서버 양쪽에서 확인. 테스트 데이터는 `[E2E-TEST]` 태그 + 정리.

## 테스트 유형별 시나리오

### 정상 흐름
- 로그인 → 대시보드 → 자산 조회/검색/상세 → 대여 신청(복수+서명+동의) → 홍보 출고 신청 → 소모품 입/출고.

### 비정상 / 경계
- 비로그인 상태에서 보호 경로 접근 → 로그인 화면 + `?next=` → 로그인 후 원경로 복귀.
- 잘못된 자격증명(관리자 회귀 스위트에서 별도 확인).
- 대여 신청 시 동의 미체크/서명 누락 → 제출 차단(HTML5 + 버튼 disabled).

### 권한 (UI + 서버 이중)
- 신청자에게 관리자 전용 메뉴/버튼 미노출: 자산 등록·수정·이동, 소모품 물품등록·재고조정, 설정·RFID 메뉴.
- 서버 강제: `/settings`,`/rfid`(미들웨어), `/assets/new`,`/assets/[id]/edit`(페이지 가드) raw HTTP 3xx.
- 서버 액션 인가: 관리자 전용 mutation은 `requireManager`, 대여/소모품 입출고는 `requireLogin`.
- IDOR: 타인 홍보 신청 취소 불가(UI 미노출 + 서버 소유권 검증) — 데이터 계층 직접 테스트로 확인.

### 동시성 / 세션
- 새로고침·새 탭 재접속 시 세션 유지.
- 로그아웃 후 보호 경로 재접근 차단.

### 모바일 / 반응형
- 뷰포트 360×800 / 390×844 / 768×1024 / 1366×768 에서 렌더 + 가로 스크롤(오버플로우) 없음.

### 보안 / 콘솔
- 콘솔·페이지 치명적 에러 없음(외부 구글시트/파비콘 노이즈 제외).

## 케이스 매트릭스 (요약)

| ID | 영역 | 핵심 확인 |
|----|------|-----------|
| A1–A5 | 인증 경계 | 비로그인 307 + next 복귀 |
| B1–B2 | 세션 | 새로고침/새 탭 유지 |
| C1–C6 | 서버 권한 | settings/rfid/new/edit 서버 차단 |
| D | 메뉴 | 신청자 5개, 설정·RFID 숨김 |
| E1–E4 | 대시보드 | 위젯 + 등록 링크 숨김 |
| F1–F8 | 자산 | 조회/검색/페이지/상세 + 수정·이동 숨김 |
| G1–G5 | 대여 | 복수 선택+서명+동의+제출 |
| H1–H4 | 홍보 | 신청→본인 취소, 타인 취소 불가 |
| I1–I4 | 소모품 | 입출고 가능 / 등록·조정 숨김 |
| J | 반응형 | 4개 뷰포트 무횡스크롤 |
| K1 | 로그아웃 | 이후 보호 경로 차단 |

## 통과 기준

- 신청자 스위트 50/50, 관리자 회귀 21/21, 서버 IDOR 5/5 모두 PASS.
- 테스트 종료 후 `[E2E-TEST]` 데이터 0건, 사용 자산 상태 원복(정상).
